# v1.7.47 — Optimización y confiabilidad
Base: v1.7.46 (SHA-256 867774faa604414f7ad44f12a1d9738f5b0fc07a5ec88699544a11dc54f41b04).

- N-07 (parcial): las seis rutas que usan transacciones comparten un presupuesto monotónico de 45 s desde la adquisición del cliente, ajustando statement_timeout a cada sentencia (máximo 25 s), serializando solicitudes sobre el cliente y permitiendo rollback después de vencer. Se descarta una conexión que no se pueda limpiar. No garantiza un plazo absoluto ante pérdida de red, ni incluye todas las consultas previas de autenticación, compresión, transmisión o confirmación incierta de COMMIT. Validar en PostgreSQL real.
- N-08/R-04: el conteo total excluye el cursor pero conserva los filtros y la fecha de corte; remaining expresa las filas desde el cursor (incluida la página solicitada) o desde el offset. La consulta de conteo y la página comparten transacción. No hay snapshot permanente entre peticiones; cambios concurrentes siguen siendo un riesgo residual N-08.
- R-02: /api/health comprueba la tabla de revocaciones y la disponibilidad de tablas y columnas académicas seleccionadas mediante LIMIT 0; devuelve 503 ante fallo. No certifica integridad de los datos ni permisos de escritura.
- P-02/R-03 (parcial): aviso explícito de que Supabase conserva el registro definitivo, copia persistente voluntaria, selección de campos necesarios, caducidad fija desde la creación (no se renueva al editar), limpieza al abrir, recuperar foco, volver a mostrar y cada minuto mientras la página ejecuta JavaScript. Se conserva recuperación de borradores; no se promete borrado con navegador cerrado ni cifrado. Desactivar en equipos compartidos.
- N-06/R-01: liberar cliente tras COMMIT y antes de serializar/comprimir/transmitir respuesta administrativa; predicado de cuatrimestre parametrizado únicamente cuando se solicita. No se elimina la descarga completa predeterminada: se preserva la exactitud de reportes, comparaciones e indicadores. N-06 parcial.
- No se reincorpora lib/http-response.js. Sin cambios de CSS, logotipos, configuración Render/TLS ni migraciones 001–010. No se aplicaron modificaciones en GitHub, Render o Supabase.
- Se mantienen pruebas aisladas anteriores con clientes simulados y se agrega consolidated-audit-check.js para la lógica de presupuesto de tiempo, rollback, total de cursor, liberación previa a respuesta, salud y privacidad. La prueba de arranque usa dependencias externas simuladas. El preflight real no concluye por pg ausente en el entorno local.
